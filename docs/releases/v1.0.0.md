# FlowForge v1.0.0

FlowForge is a distributed job processing platform built in Go with PostgreSQL
and Redis, focused on reliable asynchronous execution, scheduling and failure
recovery.

## Highlights

- Durable PostgreSQL-backed Job lifecycle, transactional outbox and Attempt records.
- Redis Streams delivery and coordination; bounded multi-worker execution.
- Heartbeats, database-time leases, stale-owner fencing and crash recovery.
- At-least-once delivery/execution and exact-key submission idempotency.
- Budgeted retries with exponential backoff/equal jitter, DLQ inspection and redrive.
- Attempt deadlines, cooperative cancellation and priority/capability-aware Claim.
- Delayed Jobs and fixed-interval recurring schedules.
- React Dashboard with transient WebSocket hints, reconnect and REST repair.
- Bounded Prometheus metrics, Grafana provisioning and optional OpenTelemetry hooks.
- Production-like Docker Compose topology, PostgreSQL TLS and Redis authentication.
- Backup/restore, restart persistence and deployment safe-abort validation.
- GitHub Actions CI, failure injection and recorded performance benchmark harnesses.

## Delivery semantics

FlowForge uses **at-least-once** execution semantics. Jobs may execute more than
once during failure recovery. Submission idempotency prevents duplicate accepted
submissions for the same key and request identity; it does not make external
effects exactly-once. Lease fencing protects database writes. Effectful executors
need their own application-level idempotency/fencing.

## Deployment

v1.0.0 includes a production-like single-host Docker reference topology and
deployment tooling validated locally and in CI. Private mode binds the gateway
to loopback for SSH-tunnel access; optional public mode applies HTTPS/Basic Auth.
Local public-mode tests use a trusted disposable CA, not public ACME.
Published GHCR images and real protected SSH/Environment deployment were not
performed. Strict SSH host verification, image identity, permissions, locking,
backup, migration, health checks and safe abort remain intact.

**Real VPS / AWS deployment is intentionally outside the required v1.0.0 scope and was not performed.**

## Recorded performance evidence

The existing Phase 9 local SLEEP matrix covers 1/4/8/16 Workers, C=1, three
repetitions each and 6,000/6,000 successful measured Jobs. All repetitions,
including slow results, are preserved in the
[baseline](https://github.com/Daniel-Cpz/FlowForge/blob/main/docs/benchmarks/phase-9-baseline.md)
and [raw summaries](https://github.com/Daniel-Cpz/FlowForge/blob/main/docs/benchmarks/phase-9-results.json).
Variation is large and throughput does not improve monotonically; these results
establish neither stable linear scalability nor production latency/recovery SLAs.
No performance-sensitive code changed during final release review; no new heavy
benchmark was run and no new performance numbers are claimed.

## Known limitations

- Single-host failure domain, maintenance downtime; no HA or autoscaling guarantee.
- SLEEP is the only executable demo Job type; no full application user/RBAC system.
- No real cloud, public ACME, browser E2E or off-host disaster-recovery validation.
- PostgreSQL `sslmode=require` encrypts without certificate identity verification;
  Redis has no TLS on the private single-host network. Certificate rotation is
  operator work; the gateway retains its upstream image's default user.
- Logical local backups and safe abort require operator restore/schema compatibility
  decisions; no automatic schema downgrade or guessed image rollback.
- External effects are not exactly-once. No general workload/scaling SLA is claimed.
- The retained pre-Phase-5 development DB remains schema 4 with its documented
  duplicate-key fixture. Migration 000005 intentionally blocks its upgrade;
  isolated schema-8 tests validate current uniqueness/concurrent replay. No retained
  data was repaired or deleted for release.
